Commands run during setup
-------------------------
Run commands from C:\laragon\www\app_qualityfriend.

1. Create the private environment file:

   Copy-Item .env.example .env

2. Edit .env and set a private local POSTGRES_PASSWORD.

3. Build and start the containers:

   docker compose up --build

4. Check the containers:

   docker compose ps

5. Confirm the development database exists:

   docker compose exec postgres psql -U qualityfriend -d qualityfriend_dev -c "SELECT current_database();"

6. Test DNS inside the application container:

   docker compose exec app node -e "require('dns').lookup('registry.npmjs.org', console.log)"

7. Recreate the app after changing its DNS configuration:

   docker compose up -d --force-recreate app

8. Install the PostgreSQL packages:

   docker compose exec app npm install pg
   docker compose exec app npm install --save-dev @types/pg

9. Create the health Route Handler directory:

   New-Item -ItemType Directory -Force -Path "app\api\health\database"

10. Restart the app so Next.js detects the new directory:

   docker compose restart app

Useful commands
---------------
Start the stack:

   docker compose up -d

Stop the stack without deleting database data:

   docker compose down

View app logs:

   docker compose logs --tail=100 app

View PostgreSQL logs:

   docker compose logs --tail=100 postgres

Rebuild after dependency or Dockerfile changes:

   docker compose up -d --build

Important: Do not use "docker compose down -v" unless the local PostgreSQL
database and all stored data should be permanently deleted.

Problems encountered and fixes
-------------------------------

1. npm install failed with EAI_AGAIN

   Problem:
   The app container could not resolve registry.npmjs.org. DNS lookup returned
   getaddrinfo EAI_AGAIN.

   Fix:
   DNS resolvers were added to the app service in compose.yaml. Docker
   Desktop/WSL networking was restarted, and the app container was recreated.
   The DNS test then returned an IPv4 address and npm installation worked.

2. /api/health/database initially returned 404

   Problem:
   Next.js did not detect the new nested Route Handler directory through the
   Windows Docker bind mount.

   Fix:
   The app container was restarted with "docker compose restart app". Next.js
   then detected app\api\health\database\route.ts.

3. PostgreSQL password question

   Explanation:
   PostgreSQL runs entirely inside Docker, but its official image needs a
   password to initialize the database user. Applications use the same private
   local password through DATABASE_URL. PostgreSQL does not need to be installed
   through Windows or Laragon.
